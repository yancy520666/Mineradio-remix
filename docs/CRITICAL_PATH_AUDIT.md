## 实际发现并补齐的三个测试缺口

1. **DNS 缓存**：原测试未检查有效期内的请求数量。将 `>` 改成 `<` 后可能多查一次，原断言仍通过；现在同时检查有效期内复用、到期边界和续期复用。
2. **汽水 VOD 地址校验**：原模拟服务器自身拒绝错误域名，掩盖了生产地址校验被删除。新增模拟服务器接受并返回可播放音频的场景，由生产代码在发送请求之前阻止恶意域名、HTTP、URL 账号、异常端口与回环地址。
3. **原版配置导入**：原测试保护了现有账号文件，但未覆盖 Remix 已有行为设置和内置歌单文件。新增不同内容的原版与 Remix 文件，确认导入不会覆盖任一已有 Remix 文件，也不改动原版文件。

这三项属于测试缺口；当前业务代码的对应保护有效，因此没有为通过测试而修改业务条件。另外新增了有／无 D 盘的缓存默认路径测试。

## rg 文本审查

规则覆盖 `window.prompt`、关闭 TLS 校验、固定盘符、部分敏感接口明文 HTTP、硬编码凭据和带 Cookie/token 字样的日志。只输出位置，不输出匹配文本或账号数据。

本轮结果：原生 prompt、TLS 绕过、所选明文接口规则、字面量凭据规则均为 0；固定盘符 3 处，日志候选 20 处。逐项结合上下文处理：

- `desktop/main.js` 的 D 盘路径是“存在则优先，否则用户目录”的分支；另外两处是 Steam 多盘目录发现。保留这些有效逻辑，不能把检出 D 盘字样等同于禁止 C 盘。
- 日志候选主要是登录布尔状态、错误消息／错误对象、凭据迁移失败说明和桌面会话标识；两处压缩 SDK 的单行匹配跨越了无关代码。本轮未发现直接输出完整账号 Cookie/token 的语句，因此没有盲删日志。
- 日志中的动态错误对象内容没有穷尽验证，文本规则也不解析完整 JavaScript。0 匹配不等于不存在所有敏感信息泄露路径；候选数同样不等于缺陷数。

## 复跑方法与边界

需要 Node.js、Git 和 rg：

```sh
node scripts/audit-critical-grep.js
node scripts/audit-critical-mutations.js
```

变异脚本复制选中的测试及受跟踪 JS 源码到系统临时目录，账号文件环境变量重定向到该目录。它不复制真实账号文件、不安装依赖、不修改工作区业务源码，也不操作运行中的播放器。每个变异必须先通过语法检查；超时、缺模块、语法异常或没有测试失败记录的非零退出均不算检出。每次变异后恢复临时源码，最后删除该临时目录。只有最终 JSON 记录写入本仓库。

选中的正常测试使用模拟接口、虚拟时钟、隔离文件或提取的实际函数。检查点测试包括隔离子进程强制结束与文件损坏恢复；缓存测试包括实际临时目录的读写。本轮没有跑整套回归、重启真实播放器、使用真实账号验证各平台，也没有模拟物理断电或验收视觉流畅度。31/31 仅说明所选错误会被这些测试发现，不能推导整个软件不存在缺陷。

新测试会被现有 `npm test` 自动发现；变异审查保留为关键逻辑变更时的手动定向工具，未增加每次 CI 都执行变异审查的成本。本轮不生成安装包，不更新 Draft 或 Release。
