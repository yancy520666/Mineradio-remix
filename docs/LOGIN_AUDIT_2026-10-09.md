# 登录与安全验证审查（2026-10-09）

> 后续状态：下列“未修复”描述保留为 451b6cf 的原始审查基线。第二批已实现登录尝试所有权、候选凭据验证、网易窗口边界、汽水取消与 Spotify 历史令牌代次保护。登录证据见 LOGIN_ATTEMPT_FIX_2026-10-09.md；真实平台仍未验证，完整审查继续进行。

## 本轮修复范围

酷狗默认是客户端协议二维码登录，由酷狗 App 扫码确认，并非启动官方桌面客户端。备用入口是官方网页。

- 客户端二维码或播放响应明确要求安全验证时，向前端传递验证状态及经 HTTPS 官方域名校验的链接。
- 验证状态不再被后续取链失败、不同音质或先前试听覆盖。
- 用户在真实可见、隔离的官方窗口操作验证码；不自动解答、不绕过验证。
- 验证过程中不根据旧 Cookie 自动关闭、不自动跳转 warmup。关窗只表示用户结束窗口，必须重试登录或播放才能确认结果。
- 验证窗口的网页 Cookie 不直接覆写已有客户端 token。

这些更改未上传 main，真实账号风控、具体验证码供应商页面及 Windows 窗口体验仍待验收。

## 其他平台：已确认但本轮未修复

审查使用隔离 VM 与假响应，未读取或登录真实账号。以下是可达路径问题，而不是宣称已经发生真实账号泄漏。

### 网易云

1. `public/js/modules/08-account/03-login-modal-flows.js` 的 `closeLoginModal` 只停止轮询，没有使 `checkQr` 已在途请求失效。关闭后返回的 803 仍可更新登录界面。
2. `server.js` 的 `/api/login/qr/check` 只检查退出登录代次，没有登记二维码 key 的替换/关闭取消。仅修前端不能防止旧请求在服务端写入 Cookie；需建立完整的服务端尝试标识和取消流程。
3. `/api/login/cookie` 会将明确 `sessionRejected` 的候选会话也视为 pending 登录，并先覆盖当前 Cookie。新登录应先验证候选，拒绝已失效会话并保留旧有效会话。
4. `desktop/main.js` 网易网页登录的正则域名判断没有完整主机边界，类似 `music.163.com.evil.test` 或含 userinfo 的地址可误匹配。应改为 URL 解析、精确 HTTPS 主机校验及顶层导航约束。

### QQ 音乐

`getQQLoginInfo` 对官方拒绝结果可能保留 `loggedIn: true` 并另设 `sessionRejected: true`；新 Cookie 提交先保存，前端网页登录/手动导入只检查 `loggedIn`，从而可能显示成功。既有登录的临时探测容错不能直接用于新登录验收，应在替换凭据前校验并明确拒绝 `sessionRejected`。

### 汽水音乐

`qishui-auth-v6/security_host.html` 的取消逻辑只处理已注册的 MFA resolver；组件/决策脚本加载期间尚未注册，取消可能被忽略。`qishui-auth-v6.js` 此时可隐藏窗口，而后续验证继续等待。需要从首次进入就建立取消状态，在每次 await 后检查，并约束加载超时。

### Spotify（历史残留，不是当前可见功能）

当前 UI 和 `/api/spotify/*` 入口已移除。保留库中仍有 token 失效路径明文写入、刷新/兑换晚于清除时写回的风险，不应把它们描述为当前用户可触发的登录故障；以后恢复功能前必须处理。

## 验收建议

- 酷狗：扫码过程中验证、已登录播放时验证、取消/关窗、验证失败后重试、重复触发、退出登录后旧窗口关闭。
- 验证结束后不自动宣称成功，不自动重放已经切走的歌曲。
- 不可达或非官方验证链接不能在特权窗口中加载。
- 网易、QQ、汽水上述问题需单独修复与回归，不能将本次酷狗测试通过视为其他平台通过。
