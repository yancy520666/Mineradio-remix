## 后续补充：左栏遮挡与雾面

用户要求继续保留两项调节，并将遮挡默认值设为 1。标题、队列工具条及歌单展开的固定标题使用独立的不透明底色，正文区域继续响应滑条；此前的列表裁剪保持不变。

静态审查确认，歌单展开容器的通用 `!important` 背景压过左栏动态背景，播客卡片也有更高优先级的固定背景。修复针对这些左栏样式覆盖。进一步核对 CSS 优先级后，通用 22px 内层模糊原本已被左栏带 ID 的禁用规则压住，因此本轮不把它算作真实的重复模糊开销，也不据此宣称性能提升。

雾面调节背后场景的模糊半径，遮挡调节背景透出量。遮挡为 1 时背景完全不透明，雾面视觉上基本不可见是正常的。单色、已经模糊或缺少细节的背景也不适合比较。实机验收时，可暂将遮挡降低到 0.55，在有细节的封面/背景前比较雾面 14 与 60，并依次检查当前队列、我的歌单、展开歌曲与播客。标题区在各密度下均应遮挡完整，正文材质应随设置变化。

不强制覆盖已有存档中的自定义遮挡值，包括旧默认 0.55。新配置和原有“恢复默认”使用 1；老配置若想整栏都不透明，可将滑条调至 1 或使用已有恢复默认按钮。没有额外新增设置项或常驻说明。

侧栏补充的 24 项定向检查通过，旧版 CSS 负对照复现 4 类覆盖/默认问题。随后完整回归遇到运行环境的临时依赖目录丢失，出现模块缺失，不能算通过；保留该次日志，按锁文件恢复依赖后再验证。没有为这些环境失败修改产品逻辑或放宽断言。

## 后续补充：长时间后台后的播放停滞

用户现象为“进度停住、无声、没有说明”。本轮用隔离的媒体/计时器模拟复现触发链缺口：原卡顿观察集中于起播后的四次检查，后续 `waiting` 及返回前台没有重新启动音频恢复观察。原有重载策略存在，但没有走到它。

另用真实 provider 处理函数配合假上游响应证实：酷狗和汽水的恢复请求可能再次返回旧 URL 缓存。针对既有恢复流程传递显式 fresh 标记，只失效当前歌曲、账号、质量相关的 URL 缓存；不会全清其它缓存，不额外绕过账号、会员或质量判断。新旧并发请求分别拥有写入资格，旧结果不能回填覆盖新链接；汽水跨 metadata 到 playback 的延迟回填也有请求归属保护。

恢复修改限定于事件驱动、有限次数的原有流程，并检查用户播放意图、曲目/请求归属及账号变化。独立审查额外覆盖了等待恢复时用户暂停、关闭音频图后的媒体替换、休眠后旧计时器集中补跑、AudioContext.resume 长时间不返回等边界。没有新增常驻后台轮询或通用歌曲下载功能。

当前连续播放能力的边界：普通 `/api/audio` 是上游流式/Range 转发，临时溢写用于当前请求的流量缓冲，不能作为下一次请求的整首缓存。汽水解密音频有受限内存缓存；专辑无缝与部分混音流程存在预读，但不等于所有队列都预先存好下一首。网络中断或系统睡眠期间不能承诺持续播放。此次重点是正确恢复与明确失败，不新增无界下载或存储占用。
